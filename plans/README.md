## Dependency notes

- **006 requires 005.** `src/api/client.ts` is a 2455-line module with ~40
  exported functions that have no unit tests. Splitting it without
  characterization tests first means refactoring untested CRUD blind — exactly
  the regression risk that makes 006 HIGH-risk. Land 005, then 006.
- 001/002/003 are independent of each other and of everything else. They can ship
  as one small PR ("client + trace hardening") or three — the executor's choice.

## Findings considered and rejected

- **Add table / slim-JSON output to `search`/`latest`** — already shipped:
  `src/cli/render/releases-table.ts`, `src/cli/render/release-json.ts`,
  `src/lib/release-display.ts` all exist. The `.context/215-*` design doc is
  stale; don't re-audit.
- **Add an App Store `create-appstore` verb** — already shipped:
  `src/cli/commands/create-appstore.ts` exists and is wired in `add.ts`. The
  `.context/247-*` design doc is stale.
- **Webhook regex accepts negative timestamps** (`src/cli/commands/webhook.ts:57`,
  `/^-?\d+$/`) — cosmetic only. A negative timestamp is still rejected by the
  `Number.isSafeInteger` + skew-window checks, and the HMAC signature must still
  match regardless. No security or correctness impact; not worth a change.
- **zod version skew** — root pins `zod@^4.3.6`, `@buildinternet/releases-api-types`
  pins `^4.4.3`. Both 4.x and compatible; dedupe naturally on the next core/api-types
  bump. Not worth a standalone change.
- **Publish tokens in working-dir `.env`** (`TAP_PUBLISH_TOKEN`,
  `NPM_PUBLISHING_TOKEN`, `STAGING_ACCESS_KEY`) — the file is gitignored (not
  committed) and the repo owner manages `.env` directly. Recommendation only:
  keep publish tokens in CI secrets rather than a developer working tree, and
  rotate them if the machine is ever shared. No code change planned.
- **Bare-slug source lookup N+1 / bulk source delete** — both require new
  **API-side** endpoints (`/v1/lookups/source-by-slug`, a batch-delete route).
  Out of scope for this client-only repo; file against the private monorepo
  instead.
